## Правила гри (оновлено 17.11.2026 після аудиту)
- 2 гравці, у кожного свій таймер (default 60 с), працюють як шахові годинники.
- Перед першим ходом іде відлік 3-2-1 з ім'ям того, хто починає; годинники в цей час стоять.
- Ведучий зараховує відповіді клавішами; гравці нічого не натискають. Скасування рішень ведучого немає.
- **Правильно** → на екрані 2 с зелена рамка і правильна відповідь → хід переходить до суперника з новим фото. Час обох гравців у ці 2 с стоїть.
- **Неправильно / Пас** (однакова поведінка, різний підпис: «Помилка · штраф» / «Пас · штраф») → червоний фон і правильна відповідь на 3 с. Ці 3 с і є штраф: таймер гравця весь цей час іде. Потім той самий гравець отримує нове фото.
- **Пауза** (`Space`): обидва годинники стоять, фото приховане.
- **Кінець гри:**
  - час гравця дійшов до 0 → він програє. Якщо це сталось під час 3-секундного штрафу, гра завершується одразу на 0:00, не чекаючи кінця показу відповіді;
  - у категорії закінчились фото → перемагає той, у кого більше часу; за однакового часу (з точністю до 0.1 с) — нічия.
- Фото в межах гри не повторюються, порядок випадковий.
- Альтернативних відповідей немає: у кожного фото одна відповідь, яку бачить ведучий.
- **Фото відповіді (опційно):** у питання може бути окреме фото відповіді (наприклад, питання — фрагмент або силует, відповідь — повне фото). Його показують у feedback-станах (зеленому й червоному) замість фото питання. Якщо окремого фото немає, показується фото питання.

## Відображення
- Таймер показує лише секунди (`0:42`); десяті з'являються в останні 10 с (`0:07.4`), разом із червоною рамкою та підписом «Останні секунди».
- «Заморожений» гравець без прозорості: час світло-сірий (`#C4C9D2`), сіра смуга прогресу, тег «Заморожено» — щоб глядачі читали час суперника навіть після стиснення відео.
- Фото: `object-fit: contain`, вертикальні — по центру на темному фоні.
- Мінімальний контраст тексту 4.5:1 (placeholder-и `#8B93A1`).

## Hotkeys ведучого
| Клавіша | Дія |
|---|---|
| `→` / `Enter` | Правильно |
| `X` | Неправильно |
| `P` | Пас (= неправильно) |
| `Space` | Пауза / продовжити |
| `Esc` | Вийти в меню (з підтвердженням) |

Hotkeys не працюють, коли фокус в `input`/`textarea` (екран налаштувань).

## Інструкція для ведучого
- Шарити саме вкладку з грою (з увімкненим «share audio») і не перемикатись з неї: `requestAnimationFrame` у фоновій вкладці зупиняється. Час рахується від позначок `performance.now()`, тому він не «пливе», але екран перестає оновлюватись.

## Стек
- Frontend: Vite + React + TypeScript, деплой на Vercel
- Backend: Supabase (Postgres, Storage, Auth)
- Realtime не потрібен: гра працює в одній вкладці, яку шарять

## Data model
- `categories`: id, name, hint, status (`draft` | `published`), cover_path, created_at, updated_at
- `photos`: id, category_id → categories, storage_path, answer_storage_path (nullable), answer, is_vertical, position, created_at
- Storage bucket `photos`: читати можуть усі, писати тільки авторизований адмін
- RLS: `select` для anon тільки на published-категорії та їхні фото; `insert/update/delete` тільки для адміна (його email або role claim)

### Epic 1 — Адмінка

- [ ] Список категорій: назва, кількість фото (червоним, якщо < 60), статус, дата оновлення

- [ ] Bulk upload drag & drop; назва файлу автоматично стає відповіддю (`fiat-500.jpg` → «Fiat 500»)
- [ ] Bulk upload: файл `<name>.answer.<ext>` автоматично прив'язується як фото відповіді до `<name>.<ext>`
- [ ] Додати / замінити / прибрати фото відповіді в картці питання
- [ ] Стиснення фото на клієнті перед upload (наприклад, до ~1600px, WebP); визначати `is_vertical` і показувати позначку «вертикальне»
- [ ] Inline-редагування відповіді, видалення фото (разом із фото відповіді в Storage)
- [ ] Валідація: фото без відповіді; публікація дозволена лише з ≥60 фото, у всіх є відповідь
- [ ] Publish / unpublish

### Epic 2 — Game engine (чиста логіка, без UI)
- [ ] State machine на reducer: `setup → countdown → turn → feedback_correct (2 с) | feedback_wrong (3 с) → turn … → finished`, плюс `paused` з будь-якого активного стану
- [ ] Таймер на `performance.now()` + `requestAnimationFrame`; у state зберігати час, що залишився, а не кількість тіків
- [ ] Shuffle фото без повторів
- [ ] Завершення: час = 0 (у т.ч. посеред штрафу — одразу); фото закінчились → більше часу перемагає, рівний час → нічия
- [ ] Статистика для кожного гравця: правильні, помилки, паси
- [ ] Unit-тести: перехід ходу, штраф, кінець часу під час штрафу, усі причини завершення включно з нічиєю, пауза
