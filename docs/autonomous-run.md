# Автономний запуск (фази 6–9)

## Підсумок

Усі чотири фази реалізовані через OpenSpec (propose → apply → archive), закомічені й запушені в `origin/main`.

**Production:** https://duel-sand.vercel.app. Гра на `/`, адмінка на `/admin`.

| Фаза | Що зроблено | Коміт |
|---|---|---|
| 6 `add-admin-categories` | Вхід через magic link лише для адмінів зі списку, список категорій і редактор. Правило публікації (≥ 60 фото, усі з відповідями) перевіряють і UI, і тригер у БД. | `8a361c4` |
| 7 `add-admin-photo-management` | Масове завантаження: стиснення до WebP ≤ 1600 px, відповідь з назви файлу, пари `*.answer.*`. Сітка фото з редагуванням, обкладинки, перший production-деплой. | `76b805a` |
| 8 `connect-game-to-supabase` | Гра бере опубліковані категорії з Supabase через signed URLs. Перші фото декодуються до старту, наступні 3 — під час гри. Mock вмикається прапорцем. | `7673ed3` |
| 9 `polish-host-experience` | Звуки з Web Audio, вимкнення звуку `M`, повний екран `F`, «Як провести гру» та шпаргалка клавіш (також на паузі). | коміт цієї фази (див. `git log`) |

Тести: 226 unit і 30 DB. `build`, `lint` та `openspec validate --all --strict` проходять. Кожну фазу перевірено в браузері на локальному стеку, production — після кожного деплою.

## Ранковий чекліст

1. **Додати себе адміном у хмарі:** `npm run db:grant-admin -- --remote <ваш email>`. У хмарі зараз немає жодного користувача.
2. Відкрити https://duel-sand.vercel.app/admin, ввести email і відкрити посилання з листа **в тому ж браузері**.
3. Створити категорію й перетягнути кілька фото, включно з парою `назва.jpg` + `назва.answer.jpg` і вертикальним фото. Перевірити відповіді, «вертикальне», заміну й видалення.
4. Публікація: для категорії з менш ніж 60 фото кнопка заблокована й показує причини. Для повної категорії публікація проходить.
5. Відкрити https://duel-sand.vercel.app, переконатися, що категорія з'явилась, і зіграти дуель. **Послухати звуки** (правильно, помилка, останні 10 с, кінець гри), спробувати `M`, `F`, `Space`, `Esc`.
6. Зіграти тестову гру через Zoom / Meet, поділившись вкладкою зі звуком (кроки є в «Як провести гру»).
7. Додати редактора: `npm run db:grant-admin -- --remote <email редактора>` і надіслати йому посилання на `/admin`.
8. Коли будуть справжні категорії, видалити або зняти з публікації три тестові: «Фігури та кольори», «Цифри», «Стрілки».

## Рішення без погодження

### Фаза 6 — `add-admin-categories`
1. Форма входу не створює акаунти (`shouldCreateUser: false`). Для невідомої адреси показується те саме підтвердження, що й для відомої.
2. БД перевіряє тільки перехід у `published`. Скрипти із secret key (seed) звільнені від перевірки. Якщо опублікована категорія потім порушує правило, адмінка показує попередження, а автоматичного зняття з публікації немає.
3. До редактора додано «Видалити категорію» з підтвердженням на сторінці. Спершу видаляються файли, потім рядок.
4. Пункт «Налаштування» прибрано, бо налаштувань немає. Кнопка зветься «Зберегти» замість «Зберегти чернетку».
5. Magic link використовує PKCE, тому посилання треба відкривати в тому ж браузері.
6. Адмінка вантажиться окремим чанком (lazy).

### Фаза 7 — `add-admin-photo-management`
1. Відповідь із назви файлу: кожне слово в нижньому регістрі пишеться з великої літери, слова зі змішаним регістром (`iPhone`) лишаються як є.
2. Файл `*.answer.*` без пари в цьому ж завантаженні прикріплюється до наявного фото з такою самою відповіддю. Якщо такого фото немає, файл потрапляє в список помилок.
3. Якість WebP 0,85 і JPEG як запасний формат. Ліміт 1600 px по довшій стороні. Орієнтація з EXIF застосовується до визначення «вертикальне».
4. Паралельно вантажаться 3 файли. Нові позиції додаються в кінець. Змінювати порядок фото в UI не можна, бо гра однаково перемішує фото.
5. Обкладинка — перше фото категорії. `cover_path` не використовується.
6. У хмарній Supabase змінено лише Auth Site URL і redirect URLs, через мінімальний конфіг. Повний `config.toml` не пушився: він перезаписав би MFA, підтвердження пошти й пул з'єднань.
7. Зона завантаження стоїть на всю ширину над сіткою, а не поруч із полями, як на артборді.

### Фаза 8 — `connect-game-to-supabase`
1. Ігрові запити явно фільтрують `status = 'published'`. Адмін, залогінений у тому ж браузері, інакше бачив би в грі чернетки через RLS.
2. Гра показує опубліковані категорії незалежно від поточної кількості фото. Правило «≥ 60» БД перевіряє в момент публікації.
3. Signed URL живуть 6 год і протягом сесії не оновлюються. Вибір іншої категорії підписує посилання заново.
4. Mock вмикається прапорцем `VITE_CATEGORY_SOURCE=mock` або автоматично, якщо немає env Supabase. У unit-тестах env Supabase порожній.
5. Перед відліком декодуються перші 3 фото, з очікуванням не довше 8 с. Під час гри декодуються поточне фото й 3 наступні (кеш на 12 зображень).
6. Три тестові mock-категорії з фази 5 лишилися опублікованими в хмарі. Видаляти їх — рішення власника.

### Фаза 9 — `polish-host-experience`
1. «Помилка» і «Пас» мають один звук (низький гудок).
2. Тікання — на кожній цілій секунді від 10 до 1, лише для активного годинника. На паузі й після кінця гри тікання немає.
3. Тембри й частоти звуків підібрані в коді (`CUE_NOTES`). Гучність одна (0,25), без регулятора.
4. `F` і `M` працюють на всіх екранах, але не тоді, коли курсор у полі вводу.
5. Інструкція ведучого відкривається панеллю на сторінці налаштувань. Шпаргалка клавіш є і там, і на паузі.
6. «Нова гра» перенесено ближче до логотипа, щоб у шапці вмістилися кнопки звуку, повного екрана й довідки.

## Блокери та пропущені задачі

- **Фаза 9, задача 3.2 (частково):** я не можу почути звуки чи перевірити реальний повноекранний режим. Логіку звуків покривають тести (подія → звук, синтезатор на фейковому AudioContext), візуальну частину перевірено в браузері. **Що зробити:** пункт 5 ранкового чекліста.
- **Тестова гра через Zoom / Meet** — це задача для людини, а не для коду (пункт 6 чекліста).

## Що зробити власнику

- **У хмарі ще немає жодного адміна.** Додайте себе й редактора: `npm run db:grant-admin -- --remote <email>`. Акаунти я не створював, бо це заборонено обмеженнями запуску.
- Видаліть або зніміть з публікації три тестові категорії, коли з'являться справжні.
- Вбудований поштовий сервіс Supabase надсилає лише кілька листів на годину. Якщо цього мало, налаштуйте власний SMTP у дашборді (Authentication → SMTP).
- Не робіть `supabase config push` для репозиторного `config.toml` на хмару. Як змінювати Auth URL, описано в `docs/setup.md` §5.
